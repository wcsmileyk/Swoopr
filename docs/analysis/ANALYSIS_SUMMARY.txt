3. ALGORITHM ANALYSIS - DETECTION METHODS
================================================================================

LANDING DETECTION (get_landing):
- Uses vAcc (vertical accuracy) as gate (median + 2.5 * MAD)
- Detects "moving": gspeed > 6 m/s AND |vspeed| > 6 m/s
- Detects "stopped": gspeed < 5 m/s AND |vspeed| < 1 m/s AND alt < 10m
- Two-stage: last moving point (120s lookback) + sustained stop (15s forward)
- Fallback: minimum of gspeed + |vspeed|

FLARE DETECTION (find_flare):
- Method A (Traditional): Peak vertical speed in 30s window before landing
  Verifies: vertical speed ≤ 5 m/s, altitude ≥ 75m AGL
- Method B (Fallback): Turn-based detection using heading rate analysis
  Looks for sustained heading changes > 8-10 degrees/second

ROTATION CALCULATION (5 methods, ranked by robustness):
1. Raw heading analysis: Direct cumulative tracking + 120° outlier rejection
2. Smoothed heading: 5-point moving average in complex domain
3. Direction-consistent: Isolates dominant turn direction
4. Full rotations: Counts 360° wraps (270°→0° and 0°→270° transitions)
5. ML-enhanced: XGBoost prediction (if confidence > 0.4)

CONFIDENCE CALCULATION:
- Distance from standard turns (90°, 270°, 450°, etc.)
- Heading smoothness scoring (penalizes direction changes > 45°)
- Turn duration validation (higher confidence for 3-15 second turns)
- Range: 0.3-1.0 (0.3 = minimum confidence, 1.0 = perfect)

KEY PARAMETERS (Highly Configurable):
- Landing: back_gspeed_min, back_vspeed_min, fwd_gspeed_max, etc.
- Flare: flare_back_win (30s), max_vspeed_threshold (5 m/s)
- Rotation: turn_rate_start_degps (45°), turn_rate_stop_degps (10°)
- All in SwoopConfig class (flights/flight_manager.py, line 81)

VALIDATION:
- rotation_validator.py: Single flight validation
- batch_validation.py: Batch error analysis
- analyze_gswoop_boundaries.py: Boundary case testing
